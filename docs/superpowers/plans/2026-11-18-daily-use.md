# Daily Use (Android first) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Chat list actions and saved drafts, actionable notifications, app lock, and name editing with coloured letter tiles on Android.

**Architecture:** Each task puts its decisions in pure Kotlin in `core` (tested on the JVM) and keeps screens thin. N4 adds the database's first migration. N5 reads mute through a small interface so it does not wait for N4. N6 gates `AppRoot`.

**Tech Stack:** Kotlin, Compose Material 3, Room, platform `BiometricPrompt`, `NotificationCompat.MessagingStyle`. No new dependencies.

**Spec:** [daily-use design](../specs/2026-11-18-daily-use-design.md)

## Global Constraints

- AGENTS.md applies in full. Plain commits, no `Co-Authored-By` or other AI trailer.
- No new dependencies. No change to cryptography, keys, MLS, push gateway, server, WebRTC, the iPhone app, or `.github/workflows`.
- Every string in `strings.xml`, exact text from design section 7. Content description on every control. Never show "codec", "kbps", "relay", "MLS", "E2EE".
- Every Gradle command: `flock /tmp/myapp-heavy.lock ./gradlew --offline -PwebrtcAar=<aar> -PwebrtcAarSha256=<hash> ...`; stop Gradle only under the lock.
- A test is seen failing on behaviour before its fix (add a stub first if needed).

## Review Focus

1. A database upgraded from version 1 keeps every chat, message and attachment (N4 migration test with a populated v1 database).
2. A muted or archived chat still receives, stores and counts messages (N4).
3. Locked app: no chat content reachable through a notification tap, share intent, recents, screenshot or the call screen (N6).
4. Notification Reply while the app is not running either sends or says "Not sent"; never silent loss, never a duplicate (N5).
5. A display name with direction-override characters, line breaks or only spaces is refused before it reaches the server (N7).

- [ ] **Step 1: Failing tests** for `ChatListOrder`: pinned first by `pinnedAt` descending, then by last message time; `visible(…, archive = false)` hides archived; `badgeCount` counts unread, unmuted, unarchived chats; the sixth pin is refused.

- [ ] **Step 4: Store.** Implement the five members in `LiveChatStore` and `SampleChatStore`; an incoming message never changes `archived` or `muted`; drafts replace the in-memory keeper's storage (keep the per-account rule: drafts are wiped with the account). Tests for each. Commit.

- [ ] **Step 4: Mark as read** action through a non-exported receiver with an immutable `PendingIntent`; it validates the chat ID against the store before acting. Test. Commit.
- [ ] **Step 5: Reply.** First read how `InboxFetchWorker` opens a session in the background. ### Task N6: App lock (design 6.3). Branch `feat/n6-android-applock`.

**Files:** new `core/.../lock/AppLockPolicy.kt` and test; `SettingsStore.kt` (`appLock: Boolean`, `lockAfterSeconds: Int`); new `app/.../ui/lock/LockCover.kt`, `DeviceAuth.kt`; `AppRoot.kt`, `MainActivity.kt` (secure flag, pending intent kept), `PrivacyScreen.kt`; `strings.xml`.

**Interfaces — produces:** `class AppLockPolicy(lockAfterSeconds: Int) { fun onBackground(nowMs: Long); fun onForeground(nowMs: Long): Boolean /* locked */; fun unlocked(); val locked: Boolean }`, starting locked when the setting is on at process start; `val appLockOn: Boolean` readable by N5.

- [ ] **Step 1: Failing tests** for `AppLockPolicy`: locked at start; Immediately locks on every return; 1 minute keeps unlocked at 59 s and locks at 60 s; a clock that jumps backwards locks; turning the setting off unlocks.
- [ ] **Step 2: Implement; run; commit.**
- [ ] **Step 3: Device auth** with platform `BiometricPrompt` allowing device credential; "no screen lock" detection through `KeyguardManager.isDeviceSecure`. Commit.
- [ ] **Step 4: Gate.** `AppRoot` composes only `LockCover` while locked; `FLAG_SECURE` while the setting is on; a notification or share intent received while locked is held and followed after unlock (reuse `openableChat`); the call screen while locked shows the caller's name only and returns to the cover. Robolectric tests: locked root has no chat list node; held intent is followed once after unlock. Commit.
- [ ] **Step 5: Settings.** Switch, "Lock after" choice, enabling requires one successful prompt, disabled state without a screen lock; reset on sign-out with the other settings. Tests. Commit.
- [ ] **Step 6: Emulator test:** with the setting on (test hook for auth), relaunch shows the cover and Unlock reveals the chat list.
