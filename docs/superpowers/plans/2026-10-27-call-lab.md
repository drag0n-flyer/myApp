# Call Lab and Phase 0 Measurements Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Tasks marked **[owner on device]** are run by the project owner on physical iPhones and a Mac. Agents write their checklists and tooling, never their results.

**Goal:** Measure what GOAL.md Phase 0 requires and publish the results:
- bytes on the wire per data mode
- voice quality under loss
- call setup and reconnect reliability
- noise-suppression cost and quality
- battery use

The measurements use a throwaway 1:1 call app ("Call Lab"), a network-emulation rig, a packet-capture byte counter, and written protocols.

**Architecture:**
- **Call Lab** is a small iOS + macOS SwiftUI app in `tools/call-lab/` with its own XcodeGen project.
  - It makes 1:1 calls with the project's WebRTC build (plan 3 `WebRTCBinary`) and the Go server's `/v1/ws` and `/v1/turn` (plan 2, lane C). It sends **plaintext** SDP inside the opaque call `payload`.
  - Every audio and video knob is set by SDP munging and `RTCRtpSender` parameters. `getStats` is written to CSV once a second.
- All logic that doesn't touch WebRTC lives in the Linux-testable Swift package `CallLabKit`: knobs, presets, SDP munging, frames and CSV.
- Supporting tooling: shell scripts for Linux `tc`/`netem`, a stdlib-only Python pcap byte counter, and a corpus and scoring toolkit for noise-suppression quality.
- Results go to `docs/measurements/` and then update GOAL.md's mode table and AppCore `DataMode.estimatedMBPer10Minutes`.

**Tech Stack:** Swift 6 / SwiftUI, XcodeGen, Swift Testing, `WebRTCBinary` (plan 3), RNNoise (BSD-3, vendored C), AVAudioEngine voice processing (VPIO), Python 3 standard library, POSIX sh + iproute2 `tc`, `tcpdump`, Apple `rvictl`, Network Link Conditioner, `afconvert`, and (after approval) `numpy`, `onnxruntime`, and ViSQOL.

**Spec:** [GOAL.md](../../../GOAL.md) §4 (Low-data calling, Video, Noise suppression), §9, §10, §11 Phase 0. The cross-plan names are in the [Build Roadmap](README.md). The server contract is in the [server design](../specs/2026-10-27-server-design.md) §7.3. This plan has no separate spec; its decisions are below.

## Design (decisions)

- **The lab never ships.** Its bundle ID is `org.example.app.calllab`. It is installed via Xcode or internal TestFlight only. Plaintext SDP is allowed here and nowhere else. No lab code is imported by `apps/apple/`.
- **Signaling uses the real server,** so Phase 0 also checks plan 2's WebSocket and TURN path:
  - Call frames: `call.invite`, `call.answer`, `call.signal`, `call.hangup` (server design §7.3).
  - `payload` is base64 of UTF-8 JSON `LabPayload` (Task L2).
  - Lab devices get session tokens from a lab-only server command (Task L1), because the lab has no passkey or associated-domains setup.
- **Knobs** (all per call, set before dialing):

  | Knob | Values |
  |---|---|
  | Opus target bitrate | 6–64 kbps |
  | ptime | 20, 40, 60, 120 ms |
  | DTX | on / off |
  | in-band FEC | on / off |
  | Max playback rate | 16 000 / 48 000 Hz (wideband vs fullband) |
  | Transport-wide congestion control (TWCC) | on / off |
  | Sender `maxBitrateBps` | any |
  | Video | off, or one ladder rung |
  | Path | direct / force relay (`iceTransportPolicy = .relay`) |
  | ICE restart | off, or after 2 s / 3 s disconnected and on network-path change |

  - 120 ms ptime needs plan 3's custom build; the lab shows "120 ms needs custom WebRTC build" when the framework rejects it.
- **Presets** mirror the GOAL.md §4 mode table. Testers pick a preset and then adjust it:

  | Preset | Opus | ptime | DTX | FEC | Playback | Video |
  |---|---:|---:|---|---|---:|---|
  | `ultraLow` | 9 000 | 60 | on | off | 16 000 | off |
  | `dataSaver` | 15 000 | 60 | on | on | 16 000 | off |
  | `balanced` | 24 000 | 20 | on | on | 48 000 | 270p15 @ 175 kbps |
  | `high` | 40 000 | 20 | on | on | 48 000 | 360p20 @ 300 kbps |

  Video rungs (GOAL §4 Video): `p180_15` at 100 kbps, `p270_15` at 175 kbps, `p360_20` at 300 kbps.
- **Bytes on the wire** means the IP packet length: the IP header + UDP/TCP header + payload, so SRTP, RTCP, STUN and TURN overhead are included and link-layer framing is not. It is always counted **on one call device** (via `rvictl` or the Mac's own interface), in both directions, from the first to the last media packet.
  - Units: 1 kbps = 1 000 bit/s; 1 MB = 1 000 000 bytes, matching AppCore `DataFormat`.
- **Speech stimulus:** a fixed 5-minute "conversation" WAV with 50% ± 2% speech activity, alternating 4–8 s talk spans with silences. It is built from LibriSpeech test-clean and fed into the caller's microphone over a cable, so every app and every run gets identical input and DTX savings are comparable.
- **Network emulation:**
  - **Relayed calls:** Linux `tc netem` on the coturn host's interface, both directions via `ifb`.
  - **Direct calls, and other apps:** iOS **Network Link Conditioner** (Settings → Developer) with identical custom profiles on **both** iPhones. The same profile table is used for both.
- **Quality metrics (offline, on the Mac):**
  - **ViSQOL v3 speech mode** (intrusive, against the clean reference, 16 kHz). Google ships it as open source with a permissive license ([paper](https://research.google/pubs/visqol-v3-an-open-source-production-ready-objective-speech-and-audio-metric/), [repo](https://www.github.com/google/visqol)). Confirm the Apache-2.0 LICENSE before use.
  - **DNSMOS P.835** (non-intrusive SIG/BAK/OVRL) for noise suppression ([paper](https://arxiv.org/pdf/2110.01763)). Confirm the license of the official `microsoft/DNS-Challenge` model files before use; a fork lists the code as MIT and the data as CC-BY-4.0 ([fork](https://github.com/framsc/DNS-Challenge)).
  - **Not PESQ or POLQA:** PESQ (ITU-T P.862) is under copyright and patents that need a paid license for commercial use ([auditory.org thread](https://auditory.org/postings/2013/502.html)).
- **Noise-suppression benchmark:** compare Apple VPIO against RNNoise on the **oldest supported iOS 17 iPhone** (an A12 device: iPhone XS, XS Max or XR) and one current iPhone.
  - **Cost:** RNNoise CPU is measured with `CLOCK_THREAD_CPUTIME_ID` around each 10 ms frame. Memory is `phys_footprint` before and after model load. Latency is the algorithmic frame delay plus measured processing.
  - **Quality:** DNSMOS on recordings of the same noisy playback; ViSQOL for RNNoise on file input.
  - GTCRN and DeepFilterNet are added later, only if the owner approves and only if RNNoise falls short (GOAL §4).
- **Comparison apps:** WhatsApp, Signal and Telegram are tested with the same two iPhones, the same NLC profile, the same stimulus and cable rig, and the same capture method. Each gets 3 runs of 5 minutes, audio only.
- **Battery:** each data point is a 30-minute audio call with the screen locked, at ≥ 80% charge at the start, not charging, on Wi-Fi with Bluetooth off, at ~20 °C room temperature. The lab logs `UIDevice.batteryLevel` and `ProcessInfo.thermalState` every 60 s. Xcode Instruments Energy Log is the second source. Each configuration gets 3 runs.

## Decisions I made — owner to confirm

1. **A lab-only server command** `appserver lab session` (Task L1) mints accounts and sessions without an invite, email or passkey, and only when `APP_LAB_MODE=1`. It touches authentication, so it needs owner review. Alternative: write a separate Go signaling relay just for the lab.
2. **A cable rig instead of speaker and microphone in a room,** for reproducible input and recording:
   - Mac audio output → TRRS adapter → caller iPhone headset-mic input.
   - Callee iPhone headphone output → Mac input.

   This needs hardware: a USB audio interface with line in and out (~US$100), plus Lightning/USB-C headphone adapters and TRRS splitter cables. The acoustic fallback is less repeatable and is documented in the protocol.
3. **Quality metrics are ViSQOL v3 and DNSMOS P.835,** not PESQ or POLQA (licensing).
4. **New tools and packages for the scoring and corpus toolkit only,** run in a Python venv on the Mac and never shipped:
   - `numpy` (BSD-3)
   - `onnxruntime` (MIT)
   - ViSQOL (via the `speequal` pip package, which says it repackages Google's Apache-2.0 code, or built from source with Bazel)
   - the DNSMOS ONNX models

   Every other script uses the Python standard library only. `tshark` is optional, for manual inspection; nothing depends on it.
5. **Corpus:** LibriSpeech test-clean (CC BY 4.0) for speech. For noise, the MUSAN "noise" subset or the DNS Challenge noise set, choosing whichever license the owner accepts after checking. The corpus is fetched by a script with SHA-256 pins and never committed.
6. **RNNoise is vendored** as source at a pinned commit inside the lab only. Plan 8 owns its use in the product.
7. **Devices:** one A12 iPhone on iOS 17.x (oldest supported), one current iPhone on the newest iOS, and one Apple-silicon Mac on macOS 14 or later.

## Global Constraints

- Lab code lives only in `tools/call-lab/`. Nothing in `apps/apple/` may import it. Bundle ID `org.example.app.calllab`.
- iOS 17.0 and macOS 14.0 minimum, Swift 6 strict concurrency, `-sampleData`-free (the lab has its own UI).
- `CallLabKit` must not import WebRTC, so it builds and tests on Linux: `cd tools/call-lab/Packages/CallLabKit && swift test`.
- Python scripts: `python3` ≥ 3.11, standard library only, unless the file is under `tools/call-lab/scoring/` (decision 4).
- No new dependency beyond decision 4 and RNNoise without the owner's approval (AGENTS.md).
- Commits: plain messages, no `Co-Authored-By` or AI trailers. Coding agents run on Sonnet 5.5.
- Units and definitions exactly as in "Design (decisions)": IP-length bytes, 1 MB = 10⁶ bytes, both directions, counted on a call device.
- Corpus, captures and recordings are never committed: `.gitignore` adds `tools/call-lab/corpus/` and `tools/call-lab/runs/`. Only summary results (Markdown + CSV under 1 MB) go in `docs/measurements/`.
- The lab's UI strings don't need the String Catalog. The lab is exempt from the app UI rules, except VoiceOver labels on its controls.

## Review Focus

1. **Capturing on the TURN host double-counts.** A relay sees both legs (caller ↔ relay ↔ callee). Expected: the counter requires `--local` (the device IP) and counts only packets with that IP as source or destination. Pinned by L7 `test_requires_local` and `test_relay_leg_only_counts_device_side`.
2. **DTX savings depend on talk time.** A stimulus that is mostly speech or mostly silence would make every mode look different. Expected: the stimulus is 50% ± 2% active. Pinned by L8 `test_stimulus_activity_ratio`.
3. **SDP munging applied twice, or to the wrong m-section,** for example video getting Opus parameters, or a renegotiation reapplying `usedtx` twice. Expected: munging is idempotent and touches only the Opus payload type of the audio m-section. Pinned by L2 `testMungeIsIdempotent` and `testVideoSectionUntouched`.
4. **Asymmetric emulation.** With NLC on one phone only, or netem on egress only, results look better than reality. Expected: the rig shapes both directions, and the protocol checklist makes the tester confirm both phones' profiles. Pinned by L6 `test_apply_shapes_ingress_and_egress`.
5. **A stats CSV whose columns drift between runs** breaks cross-run comparison. Expected: one fixed header, and missing values written as empty fields, never by dropping a column. Pinned by L2 `testCSVHeaderIsFixed` and `testMissingValuesAreEmpty`.

## Task L7: Packet-capture byte counter

**Files:**
- Create: `tools/call-lab/pcap/pcapbytes.py`, `tools/call-lab/pcap/test_pcapbytes.py`, `tools/call-lab/pcap/pcapfixture.py` (writes synthetic pcap files for the tests)

**Interfaces — Produces:**
- CLI: `python3 pcapbytes.py <file.pcap> --local <ip>[,<ip>] [--peer <ip>,…] [--exclude-ports 53,5353,443] [--start <epoch s>] [--end <epoch s>] [--udp-only]`
- It prints JSON: `{"duration_s", "up_bytes", "down_bytes", "up_packets", "down_packets", "up_kbps", "down_kbps", "bytes_per_min", "mb_per_10min"}`
  - `bytes_per_min` covers both directions.
  - `mb_per_10min = round((up_bytes+down_bytes)/duration_s*600/1e6, 2)`.
  - The duration runs from the first to the last counted packet, unless `--start`/`--end` are given.
- Bytes are the IP length: the IPv4 total length, or the IPv6 payload length + 40.
- Supported link types: 0 (null), 1 (Ethernet), 12/101 (raw), 113 (Linux SLL), 228/229 (IPv4/IPv6), 276 (SLL2), and 149/258 (Apple PKTAP, skipping its header by its length field). Any other link type exits 2 with `unsupported linktype N`. pcapng (magic `0x0A0D0D0A`) exits 2 with `pcapng not supported: re-save as pcap (tcpdump -w without -P, or editcap -F pcap)`.
- `--local` is required; without it, the script exits 2 with `--local is required (count on the call device, not the relay)`.
