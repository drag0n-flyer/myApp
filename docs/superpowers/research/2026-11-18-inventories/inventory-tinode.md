# Tinode apps: user-visible feature inventory (from source)

Sources: `tinode_ios` (Swift, UIKit/storyboard, SQLite.swift, WebRTC, MobileVLCKit), `tinode_tindroid` (Java, Fragments, SQLite, WebRTC, ExoPlayer/Media3, WorkManager), `tinode_chat/docs`.
Paths: iOS = `tinode_ios/Tinodios/...` (SDK in `TinodeSDK/`, DB in `TinodiosDB/`, push extension `TinodiosNSExtension/`). Android = `tinode_tindroid/app/src/main/java/co/tinode/tindroid/...` (SDK `tinodesdk/src/main/java/co/tinode/tinodesdk/`), strings in `app/src/main/res/values/strings.xml`.
Short forms: `A:` Android, `i:` iPhone. "Both" = same on both.

Big picture: plain-vanilla, utilitarian messenger. NO reactions, NO in-chat message search, NO per-chat media gallery, NO link previews in clients, NO @mention picker, NO unread marker, NO message drafts that survive restart, NO voice-message speed control, NO image editor, NO reply-from-notification, NO share extension on iPhone. Strong points: pinned messages, quote/reply/forward/edit with Drafty rich text, voice notes with waveform + lock/cancel gesture, CallKit/ConnectionService calls, tag-based user discovery, QR add-by-ID, white-label branding by code, group permission model.

---
## 1. Onboarding

- **Login**: login (username) + password. Empty field -> inline field error "Login required" / "Password required". Last-used login is pre-filled (A: pref `pref_lastLogin`). Progress overlay "Logging in..." (i). Server error shown as "Login failed: <server text>". `A: LoginFragment.java`, `i: LoginViewController.swift`.
- **Sign-up**: avatar (optional, camera/gallery), login (must not contain ":"), password, full name (required), optional description, plus credentials the SERVER requires (email and/or phone; field set depends on server's required-credential methods, default `email`). Server can reject login/email -> error attached to the specific field ("Login rejected", "Email rejected"). "Service unavailable at this time" toast if server params can't be fetched (sign-up button disabled). `A: SignUpFragment.java`, `i: SignupViewController.swift`. Phone entry has country-code aware field (`widgets/PhoneEdit.java`, i: `PhoneNumberTextField`).
- **Credential verification**: after sign-up/login, if server demands validation the app shows a "Enter confirmation code" screen (code sent by email/SMS); wrong code -> "Invalid code"; cancel returns to login. App restarts directly into this screen if validation is pending (`db.isCredValidationRequired()` in A `LoginActivity.java`). `A: CredentialsFragment.java`, `i: CredentialsViewController.swift`.
- **Password reset ("Forgot password")**: choose email or phone -> "Request code" -> separate "I have code" shortcut -> enter code + new password -> "Password changed". Explanatory text tells the user whether an email or SMS will be sent. Unknown address -> "Invalid or unknown address". `A: PasswordResetFragment.java`, `i: ResetPasswordViewController.swift`.
- **Server selection**: A: in-app Settings screen on login (server address, "Use secure connection" TLS checkbox; subtitle "Connecting to '<host>'") (`LoginSettingsFragment.java`, `res/xml/login_preferences.xml`). i: NOT in app; lives in iOS Settings app (`Settings.bundle/ConnectionSettings.plist`: host name default 127.0.0.1:6060, "Secure connection"). Emulator host 10.0.2.2:6060 on A.
- **White-label / branding by code**: "Configure connection" button on login: enter a short configuration code OR scan a QR code; app fetches a client config (api_url, service name, small/large icon, ToS/privacy/contact URLs) from a hosts service and re-brands the login screen ("Powered by Tinode" shown when custom). A also reads the Play install referrer on first run to auto-apply a code. `A: BrandingFragment.java`, `BrandingConfig.java`; `i: BrandingViewController.swift`, `QRScanner.swift`.
- **Account deletion**: Account > Security > "Delete account"; irreversible-warning dialog; deletes the user hard (A: `delCurrentUser(true)`). `A: AccSecurityFragment.java`, `i: SettingsSecurityViewController.swift`. No re-authentication prompt found.
- **Logout**: confirm dialog "Are you sure you want to logout?"; same Security screen.
- **Multiple accounts**: not present as a user feature. DB can hold several account rows but exactly one is "active"; no account switcher UI. A registers with the system AccountManager (account type + sync adapter) and has `EXTRA_ADDING_ACCOUNT`, but still one active login (`account/Utils.java`, `db/AccountDb.java`; i: `TinodiosDB/AccountDb.swift getActiveAccount`).
- **Startup behaviour in awkward case**: if offline at launch but a local account exists, app opens straight to the cached chat list with offline indicator (comment block in A `LoginActivity.java`). Token login, no password stored.

## 2. Chat list

- **Row contents** (`A: ChatsAdapter.java` + `res/layout/contact.xml`; `i: widgets/ChatListViewCell.swift`): avatar (photo or letter tile) with online dot (green/grey; hidden for channels and Saved messages); title; subtitle = preview of last message (rich-text preview, media shown as icon/label) or the private comment if no messages; delivery tick on the last message when it is yours (clock / sent / delivered / read); unread badge (number, "9+" cap); icons for group, channel, muted, blocked, archived, deleted; trust badges (verified / staff-managed / "danger"/untrustworthy). NO timestamp column in the row.
- **Unread badge**: count from server read-seq. i: app icon badge = total unread (`AppDelegate.swift` `applicationIconBadgeNumber = Cache.totalUnreadCount()`). A: no launcher badge code.
- **Pinning chats**: A only. Select chat(s) (long-press multi-select with ActionMode) > Pin/Unpin; pinned rows sorted to top with a distinct background + pin indicator (`getPinnedRank`, `me.pinTopic`). i: not present.
- **Archiving**: A: multi-select > Archive; menu "Archived chats". i: swipe action "Archive"; footer button "Archived Chats (N)" on chat list; archive screen with "Unarchive" swipe (`ArchivedChatsTableViewController.swift`). Archived chats are hidden from the main list.
- **Muting**: A: multi-select > Mute/Unmute, or chat menu, or info page switch. i: info page switch (no list swipe). Muted shows a bell-off icon; muted topics don't push.
- **Delete**: A multi-select > Delete (confirm "delete these chats?"); i swipe "Delete" (red) + archive.
- **Search in chat list**: not present on either. Search exists only in (a) Find/New chat (people/groups), (b) A "Send to..." share target picker (`SendToActivity.java`, `ChatsAdapter.setTextFilter` matches name, note, comment).
- **Swipe actions**: i only: trailing swipe = Delete + Archive. A none (uses long-press multi-select; action bar shows Delete/Mute/Archive/Pin).
- **Empty state**: text "You have no chats  ¯\_(ツ)_/¯" (both). A shows one 'empty' list item.
- **Connection status**: A: animated thin line under the toolbar (`widgets/ConnectionAnimView.java`) + a toolbar item "Working offline" shown while disconnected (tapping forces reconnect-now). i: only a toast "Connection to server lost." on drop (`UiUtils.swift UiTinodeEventListener`) and "You are offline." toast on failed actions; no persistent indicator.
- **Typing/online**: online dot on avatar in list. Typing animation is NOT in the list; it is in the chat toolbar avatar (see 3). Self "Saved messages" chat has no dot.
- **Deleted/gone peers**: row dimmed (alpha 0.8) with deleted icon, avatar greyed.
- **Blocked list**: "Blocked contacts" screen (A `ChatsFragment` banned mode; i `BlockedContactsTableViewController.swift`, swipe Unblock/Delete).
- **Pending invitations**: when someone starts a chat with you, opening it shows "You are invited to start a new chat. What would you like?" with Accept / Ignore / Block (A `MessagesFragment.showChatInvitationDialog`, i `Invite reaction button` strings).

## 3. Chat screen

- **Bubble layout**: left/right bubbles with tails on the last bubble of a run from the same sender (A view types TIP/AVATAR/DATE bitmask in `MessagesAdapter.java`; i `MessageBubbleDecorator.swift` styles single/first/middle/last). Group chats: avatar + sender name on incoming; channels: no avatars. Time in bubble; "edited" label on edited messages; delivery tick inside own bubble. Unknown sender shown italic "Not found".
- **Grouping**: consecutive messages from same sender within same date are one run (tail only on last).
- **Date separators**: centred upper-case chip ("TODAY"/date) above first message of each day (A `date_bubble.xml`, i `newDateFrame` in `MessageViewLayout.swift`).
- **Delivery/read marks**: clock (queued/sending), warning (failed), single tick (sent), double tick (delivered), double tick tinted (read). Read/received counts come from per-recipient receipts, so in groups "read" = at least one reader. `A: UiUtils.setMessageStatusIcon`; `i: UiUtils.deliveryMarkerIcon`. Users can turn read receipts off (see 11).
- **Reply/quote**: A: long-press selects message -> action bar Reply. i: long-press popup menu Reply. Shows a quote preview bar above composer (first ~64 chars, thumbnail for image/video) with cancel. Sent message embeds the quote; tapping a quote in a bubble scrolls to and flashes the original (if loaded). `A: MessagesAdapter.scrollToAndAnimate`, `format/QuoteFormatter.java`, `SendReplyFormatter.java`; i: `format/QuoteFormatter.swift`, `SendReplyFormatter.swift`.
- **Forward**: pick message > Forward > chat picker (with search) > preview panel in destination composer showing "forwarded from <mention of original sender>" > send. Single message only. `A: ForwardToFragment.java`, `SendForwardedFormatter.java`; `i: ForwardToViewController.swift`, `widgets/ForwardMessageBar.swift`. Also A system share (ACTION_SEND) from other apps into a chosen chat (`SendToActivity.java`). i: no share extension.
- **Edit**: own, synced, text-only messages (not those with audio/file/form/image/video/call entities; i also blocks quotes) -> Edit puts text into composer with an "editing" preview and a tick button; sent as a replacement so recipients see "edited". `A: MessagesAdapter.updateSelectionMode`, `i: MessageViewController+MessageCellDelegate.swift createPopupMenu`.
- **Delete**: A: select 1..n messages > Delete > dialog; if you have delete permission a checkbox "Also delete for <peer>" / "Delete for everybody" (hard delete) else delete-for-me only. Saved messages chat: always hard delete. Channels: subscribers cannot delete. i: popup shows "Delete for me" and (if permitted) "Delete for all"; "Delete for all" hidden when message older than server limit `msgDeleteAge` unless you are owner (A has no age check). Deleted messages render as "message deleted"/"Content deleted" placeholders.
- **Reactions**: NOT present (no code in either app).
- **Copy**: A: action bar Copy (multi-select concatenation, `format/CopyFormatter.java`) with toast "Copied to clipboard"; i: popup Copy of one message.
- **Select multiple**: A yes (long-press, then tap to add; count in title; Reply/Forward only when 1 selected; Edit only if 1 own editable; Pin only for managers/admins). i: no multi-select; one message at a time via popup (`UIMenuController`).
- **Scroll-to-bottom**: floating button appears after scrolling up >2 items, hides near bottom (A `goToLatest`; i `goToLatestButton`). Sending a message auto-scrolls to bottom.
- **Unread marker / "new messages" divider**: not present.
- **Message search inside chat**: not present.
- **Pinned messages**: up to 5 pinned per chat (`MAX_PINNED_COUNT = 5` in SDK). Admins/owners get Pin/Unpin on a message. Pinned bar under the toolbar: pager with dot indicator, shows text/preview of each pinned message, swipe between pins, tap to jump to message, [x] to unpin (managers). `A: fragment_pinned*.xml`, `MessagesFragment.PinnedAdapter`; `i: widgets/PinnedMessagesView.swift`, `widgets/DotSelectorImageView.swift`.
- **Drafts**: A: unsent text and reply/edit/forward state are kept only in fragment args while the app process lives (not persisted to DB; lost on process death). i: not present.
- **Link previews**: not present in clients (server offers `/v0/urlpreview` in docs/API.md but neither app calls it). URLs are auto-linked and tappable.
- **Text formatting**: composer text parsed as markdown-like Drafty on send: `*bold*`, `_italic_`, `~strike~`, `` `code` ``, links, line breaks (docs/drafty.md; `Drafty.parse` in A `MessagesFragment.sendText`, i `Drafty(content:)`). No formatting toolbar. Incoming also supports highlight, hidden, buttons, forms, rows. Messages made of 1-5 emoji only are rendered enlarged (scale 1.26-3.0x; A `MessagesAdapter`, i `FullFormatter.swift`).
- **Mentions / hashtags**: rendered (mention coloured by user-id hash; used in forwarded-from header) but there is NO @-autocomplete in the composer, and hashtags are not interactive (A `FullFormatter.handleHashtag` returns null).
- **Interactive messages**: Drafty buttons (`BN`) can post back to a bot, forms (`FM`) render; tap handlers `tinode://post` etc. (i `MessageViewController+MessageCellDelegate.swift`).
- **Call records in chat**: a call appears as a bubble "Incoming/Outgoing call" with arrow icon, duration or status (missed / declined / disconnected / busy / cancelled) coloured green/red. `A: FullFormatter.handleVideoCall`.
- **Chat toolbar**: avatar+name; subtitle = last seen ("just now", "5 min ago", "never") when offline, blank when online; group shows subscriber count; typing = green animated overlay on avatar for 4 s after peer keypress (A `UiUtils.toolbarTypingIndicator`, i `AvatarWithOnlineIndicator+TypingAnimation.swift`). No "typing..." text.
- **Pull to refresh**: A: swipe-down loads older messages.
- **Disabled-composer states**: "Peer's messaging is disabled" bar with Enable button (when you've disabled the peer's right to write to you); "Not available" overlay when you lack write permission; "No access to messages" when you lack read; invalid/deleted topic screen "Conversation not found or invalid" (A `fragment_invalid_topic.xml`, `fragment_messaging_disabled.xml`).
- **Empty chat**: i "No messages in the conversation".
- **Background**: A: wallpaper (see 11). i: plain, dark/light.
- **Notable A selection nuance**: tapping a bubble outside selection mode flashes it (and jumps to quoted original if it is a reply).

## 4. Composer and attachments

- **Composer** (`A: fragment_send_message.xml`, `i: widgets/SendMessageBar.swift`): multi-line text field, attach-file (paperclip), attach image/video, mic button that turns into send when text exists. "Send on Enter" option (A, hardware keyboards). Rich-content paste into the field (images/GIFs via `ContentInfoCompat`, A `MessagesFragment` line ~1700).
- **Photos/videos**: A: attach dialog with Camera / Gallery / Video (`widgets/AttachmentPickerDialog.java`, `UtilsMedia.java`, Android Photo Picker). i: `UIImagePickerController` action sheet (camera/library, image+movie) (`widgets/ImagePicker.swift`; code notes original-quality video needs PHPicker, a TODO). Both then show a preview screen with optional caption ("Image caption"/"Title of the video") before Send (`A: ImageViewFragment`/`VideoViewFragment`, `i: widgets/SendImageBar.swift`, `ImagePreviewController.swift`, `VideoPreviewController.swift`).
- **Image processing**: auto-rotate by EXIF, downscale to max 1024 px, tiny blurred preview thumbnail (64 px) inlined so bubble shows instantly; video gets poster frame (<=640 px) + duration/size.
- **Files**: any file via system picker; shows file-preview screen (name, type, size) with Send; message shows file icon, name (middle-ellipsised if long), size, "save" link. `A: AttachmentHandler.java`, `FilePreviewFragment.java`; `i: FilePreviewController.swift`.
- **Size limits**: server-driven: small attachments (< ~190 KB, derived from `maxMessageSize` 256 KB * 3/4) are inlined as base64; bigger ones upload out-of-band over HTTP; absolute cap = server `maxFileUploadSize` (default 8 MB). Over limit -> toast/inline error "The file size X exceeds the Y limit." Zero-byte file -> "Unable to attach this file". Video poster larger than the video is rejected. (A `AttachmentHandler.uploadMessageAttachment`; i `MessageViewController+SendMessageBarDelegate.swift`).
- **Voice messages**: hold mic -> recording starts (A: long-press, needs RECORD_AUDIO prompt); while holding: slide LEFT to cancel (trash zone) or UP to lock (haptic feedback on zone reached, `widgets/MovableActionButton.java`; i `SendMessageBar.longPressed`). Release = send. Locked mode shows live waveform + timer + Stop / Delete / Send; after Stop can Play/Pause preview and tap on the waveform to seek (A) before sending. Min length 2 s (A) / 3 s (i): shorter recordings are discarded; max 10 min (auto-stops). While recording the peer sees a recording notification (`noteRecording`). Waveform = 96 amplitude samples stored with message. Recorded as AAC in MPEG-4 (A). Playback in bubble: play/pause button + waveform that fills with progress + tap/drag to seek; only one audio plays at a time; playback released when bubble scrolls away. i uses VLC for playback (`RecordedMediaPlayback.swift`, `MediaRecorder.swift`, `format/WaveTextAttachment.swift`); A `widgets/WaveDrawable.java`, `MediaControl.java`. Playback speed control: not present.
- **Camera**: A: system camera (photo/video) via launcher with permission handling and "Camera not accessible" toast; i: camera source in picker.
- **Image editing/cropping**: not present for chat images. Avatar pick has crop: A square pan/zoom overlay circle (`ImageViewFragment` avatar mode, `OverlaidImageView.java`, min 8 px, "Image is too small"); i `allowsEditing` system crop. Avatars scaled to <=384 px, inlined if <=4 KB else uploaded.
- **Upload progress / cancel**: A: circular progress + cancel [x] in the bubble, then "canceled" or "failed" label (`CircleProgressView.java`); i: progress view with cancel (`widgets/ProgressView.swift`, `LargeFileHelper.swift`). While an attachment uploads the bubble is non-clickable.
- **Download**: A: "save" link downloads via system DownloadManager to Downloads (notification, Wi-Fi or mobile, no roaming) or MediaStore on Q+; "Failed to download the file", "No application can view the file of this type". i: tap file -> download to app then share sheet (`UiUtils.swift` UIActivityViewController).
- **Failed sends / retry**: messages are written to local DB first (status draft/queued/sending/failed). A: bubble shows "processing..." / "failed" placeholders; "Send now" action-bar item resends everything pending; automatic sync on reconnect/subscribe (`MessageActivity.syncAllMessages`). Uploads use WorkManager with network-connected constraint (A `AttachmentHandler.java` line ~253) so they resume when network returns. i: pending messages re-sent by `topic.syncAll()` on subscribe (`MessageInteractor.swift` line ~226). No explicit tap-to-retry on a failed bubble found on i.

## 5. Media viewing

- **Image viewer**: full-screen with pinch-zoom and pan, double-bounds clamping (A `ImageViewFragment.java` matrix based; i `ImagePreviewController.swift` UIScrollView). Shows file name, type, dimensions/size panel. Save to gallery action ("Image saved to gallery") / download.
- **Video player**: A Media3 ExoPlayer fullscreen with controls (`VideoViewFragment.java`); i custom controls: play/pause, scrubber + elapsed/duration, mute, save, spinner (`VideoPreviewController.swift`, VLC). Poster frame + duration overlay in the bubble before play.
- **Audio**: inline in bubble (see 4). **Files**: open with system app.
- **Save/share**: save image/video to library; A "Download"; i share sheet. Share-out of arbitrary message: not present (only Forward inside app).
- **Media gallery per chat** (all photos/files in a conversation): not present.
- **Wallpaper** background for chat (A only, see 11).

## 6. Contacts and finding people

- **New chat screen**: tabs for contacts/search, "By ID", and "Group" (`A: StartChatFragment.java`, `FindFragment.java`, `AddByIDFragment.java`; `i: NewChatTabController.swift`, `FindViewController.swift`, `AddByIDViewController.swift`).
- **Search by name/tag**: search box "Search by tags". Queries are sent to server `fnd` topic after a 1 s debounce (A `SEARCH_REQUEST_DELAY`), min 4 chars (server tag length). Smart rewriting: input that looks like an email -> `email:...`, a phone -> `tel:...` (E.164 normalisation using locale), otherwise treated as alias (`@alice` -> `alias:alice,alice`); comma = OR, space = AND (docs/API.md "Query Language"). Results merge local phone-contact matches and the server "Directory". Section headers "Phone Contacts" / "Directory" (i: "Local Contacts"/"Directory"). Progress spinner while searching; "No results"/"Enter search query" empty states. Group/channel discovery uses the same tag mechanism (groups can have tags set by owner).
- **Phone contacts**: with Contacts permission the app uploads the user's contact emails/phones as a search query (i `account/ContactsSynchronizer.swift` re-syncs on contact-store change and app foreground) and lists matches; without permission i shows "Search functionality limited. Grant Contacts permission." A also writes Tinode users back INTO the Android Contacts app as a sync-adapter account (rows "Tinode profile", "Send Tinode message", call action) (`account/ContactsManager.java`, `services/ContactsSyncAdapter.java`, `res/xml/contacts_source.xml`).
- **QR codes**: "My Code" shows a QR of `tinode:id/<usrId>` (A also on group info "Show QR code"); "Scan code" opens camera QR scanner; scanned ID opens/creates chat (A `UiUtils.generateQRCode`, `widgets/QRCodeScanner.java`; i `QRScanner.swift`, `Utils.swift` CIQRCodeGenerator). Also by-ID: type or paste a user/group ID ("Enter ID of a group or user"). Each user can also have an alias (@name) that is searchable; copy-ID and copy-alias buttons.
- **Invite**: "Invite" menu shares text "Check out Tinode Messenger ... https://tinode.co" via the system share sheet (generic, not a per-user or per-group link). A declares an https app-link for web.tinode.co on `LoginActivity` (branding config), no per-chat join links found.
- **Block**: info page > Security > "Block contact" (confirm "Block X?") revokes your J/P access to that P2P (`-JP`); appears in "Blocked contacts"; unblock via list. Group: member action "Block" (ban) removes and bans. Invitation dialog also has Block.
- **Report**: "Block and report" (contact/group/channel): sends a JSON message `{action:"report", target:<topic>}` to the server `sys` topic, then blocks (`A: TopicSecurityFragment.ACTION_REPORT`; i `actionReportContact/Group`). Confirm text "Block and report X?".
- **Verified/staff/untrusted badges** from server `trusted` fields on avatars/rows/info.

This selection is permanent."), member chips picker (at least one member required: "Add at least one group member"). `A: CreateGroupFragment.java`, `EditMembersFragment.java`; `i: NewGroupViewController.swift`, `EditMembersViewController.swift`.
- **Add/remove members**: group info > "Add members" (needs share/invite permission); manage members screen with chips. Per-member action sheet: View profile, Send message, Change permissions, Make owner, Remove, Block ("Remove and ban X from group?") (`dialog_member_actions.xml`, A `TopicInfoFragment` lines ~300-375). Only approvers see Remove/Block; only owner sees Make owner. Toasts "Can't change permissions for this user", "Can't make this user owner".
- **Roles/permissions**: access-mode bitmap J,R,W,P,A,S,D,O (join, read, write, presence/notifications, approve members, share/invite, delete messages, owner) shown as labelled checkboxes ("Join, Read, Write, Receive notifications, Approve new members, Invite new members, Delete messages, Full control (owner)"). Per-member, plus topic defaults for "Authenticated users" and "Anonymous users" ("New members automatically receive these permissions"). Role chips in lists: owner, admin, read-only, write-only, blocked, invited, requested, pending (`A: UiUtils.accessModeLabels`, `widgets`/`dialog_edit_permissions.xml`; i `widgets/PermissionsEditViewController.swift`). - **Group avatar/description**: editable by owner (title, alias, description, private note, tags, avatar) in "General" settings; others see read-only.

- **Channels**: broadcast; unlimited read-only subscribers; shows subscriber count, channel icon in list, no per-message avatars, subscribers cannot delete messages, "Report channel".
- **Pending join requests/invites**: statuses "invited", "requested", "pending" labelled in member lists.

## 9. Calls

- **Scope**: one-to-one audio and video (WebRTC) only; group calls absent. Call buttons shown only in P2P chats AND only when the server advertises ICE servers (`iceServers` param) else "Calling not supported"/"Video calls unavailable". Signalling relayed through server notes, doc: `tinode_chat/docs/call-establishment.md`.
- **Starting**: A: toolbar phone + video icons. i: nav-bar call button -> action sheet "Audio-only / Video / Cancel" (`MessageViewController.swift navBarCallTapped`).
- **Incoming call UI**: i: CallKit native full-screen (PushKit VoIP push wakes app; `supportsVideo`, `includesCallsInRecents = false`, one call per group) (`CallProviderDelegate.swift`, `CallManager.swift`, `AppDelegate.swift pushRegistry`). A: self-managed Telecom `ConnectionService` (`PhoneAccount.CAPABILITY_SELF_MANAGED | VIDEO_CALLING`, `services/CallConnectionService.java`, `CallConnection.java`), ongoing call notification with `CATEGORY_CALL`, ringtone, full-screen `IncomingCallFragment` with Answer / Decline (`res/layout/fragment_incoming_call.xml`), separate notification channel "Video calls".
- **Ringing timeout**: incoming UI auto-dismissed after server `callTimeout` (+5 s, default 30 s) (i `CallManager.swift`). Missed/declined/busy ends are recorded as chat messages.
- **In-call controls**: A: speakerphone toggle (video calls default to speaker), mute mic, camera on/off, hang up, enter Picture-in-Picture (controls hidden in PiP), exit-fullscreen button, local self-view. i: speaker toggle (earpiece/speaker, restored after audio route change), mic mute, camera toggle, hang up, local+remote renderers (Metal), name label on remote video; screen kept awake during call (`isIdleTimerDisabled`). Sound effects: outgoing ring/dialing and call-ended tones (i `call-out.m4a`, `dialing.m4a`, `call-end.m4a`; A `res/raw/call_out.m4a`, `call_ended.m4a`).
- **Call history**: no dedicated call log; each call is a chat message (see 3) with direction, duration, outcome. i `includesCallsInRecents=false` so not in the Phone app Recents.
- **Network change**: no ICE restart or reconnect-in-call logic. ICE state FAILED/CLOSED -> plays "call ended" sound and closes the call after ~0.7 s (A `CallFragment.onIceConnectionChange`; i `peerConnection didChange newState` -> `closeCall()`). The signalling websocket reconnect (A `reconnectNow` on network available) does not rescue an active media session.
- **Permissions**: mic/camera checks with fallback messages (i `CallViewController.permissionsCheck`). A call activity is orientation-locked.

## 10. Notifications

- **Transport**: FCM on both (i also PushKit VoIP for calls). Server decides content; client resolves sender names locally.
- **Content**: P2P: title = sender name, body = message text (rich text rendered; media -> label; fallback "New message"). Group: title = group name, body = "Sender: text". New chat invitation ("sub"): title "New chat", body = sender or group name. (`A: services/FBaseMessagingService.java`; `i: TinodiosNSExtension/NotificationService.swift` mutates the push in a Notification Service Extension using the shared DB, and fetches missing user card if unknown.)
- **Suppression**: no alert if you are already looking at that chat (A `UiUtils.getVisibleTopic`; i `AppDelegate willPresent`). "silent" pushes (e.g. message read on another device) cancel the shown notification (A `nm.cancel(topic,0)`). Deleted subscription: silent. Call pushes routed to call UI instead of a normal notification.
- **Grouping**: none. A uses one notification per chat (tag=topic, id=0) which is replaced by the newest message (no history stacking, no summary, no `MessagingStyle`). Visibility private (content hidden on lock screen), high priority, default sound, avatar as large icon.
- **Reply from notification / mark-as-read action**: not present (no RemoteInput/UNTextInputNotificationAction anywhere).
- **Tap**: opens the chat; i connects and logs in first if needed, toast "Failed to connect to server" on failure.
- **Mute options**: per-chat mute only (info page / A menu); no timed mute ("1 hour"), no per-chat custom sound. A channels: `new_message` and `video_calls` Android notification channels (system settings control sound). Incognito mode (see 11) hides your presence.
- **Badge counts**: i app icon badge = total unread; A none.
- **Background data fetch**: on push, app fetches the new message content/metadata (A `tinode.oobNotification`, i `SharedUtils.fetchData`) so the chat is current when opened.

## 12. Offline and reliability

- **Local DB**: SQLite on both (A `db/*.java` DB version 21; i `TinodiosDB/*.swift` SQLite.swift, schema 111, shared with the notification extension via app group). Tables: account, topic, subscriber, user, message. It is treated as a CACHE: on schema upgrade both drop and re-download everything but retain the logged-in account and push token (`BaseDb.onUpgrade`, i `BaseDb` drop-and-recreate). Caveat: locally queued unsent messages would be lost on such an upgrade.
- **Message states**: draft(10) / queued(20) / sending(30) / failed(40) / synced(50) / deleted hard(60) / soft(70) / delete-range marker synced(80) (`db/BaseDb.Status`).
- **Offline send queue**: messages and deletions are stored locally first and shown immediately with a clock; on (re)subscribe `syncAll()` publishes queued messages and sends pending soft/hard deletes (SDK `Topic.java syncAll`, `Topic.swift syncAll`). Offline deletes are queued too.
- **Offline browsing**: cached chats and messages are readable offline; actions needing network show "You are offline" toast (A "No connection"). Offline-at-launch opens cached UI.
- **Reconnect**: exponential backoff with jitter: delay = 1 s * 2^n + random(0..1 s*2^n), n capped at 10 (~34 min max) (A `ExpBackoff.java`; i `Connection.swift ExpBackoffSteps`). Backoff resets on successful connect. A: on network-available callback calls `reconnectNow` immediately (cuts any backoff wait) (`TindroidApp.java` NetworkCallback). Both: websocket auto-reconnect, token re-login; connection dropped when app goes background to save battery (A `onStop -> maybeDisconnect`), push wakes it (A `ProcessLifecycleOwner`).
- **Sync after reconnect**: re-subscribe to topics, fetch metadata and missed messages by seq; read/recv receipts and deletions merged; push-delivered data is stored via out-of-band notification path.
- **Pagination**: newest 20 (A) / 24 (i) messages loaded; scrolling within 4 items of top, or pull-to-refresh (A), loads one more page. Before querying the server the client checks local DB for GAPS (`getMissingRanges` / `missingMessageRanges`) and requests exactly the missing seq ranges, else loads from DB only. Messages are never unbounded in memory (page multiplier `mPagesToLoad`).
- **Read notifications**: `noteRead` sent after a 1 s delay (A `READ_DELAY`) so quick scroll-through doesn't spam; sent only if "Send read receipts" on.
- **Robustness hacks worth copying**: RecyclerView IOOBE guard when two uploads start together (A `MessagesFragment` onLayoutChildren try/catch); oversized-blob cursor guard ("misconfigured server") in adapter; stable item ids for list animation.
- **Server limits are obeyed dynamically**: max message size, max file size, message delete age, call timeout from `{ctrl}` params at login.
